You want a change checked against the cases your team cares about, with a report a reviewer can inspect. Start with validation, then run scenarios against a configured provider. A passing run describes those checks and inputs; it is not a general guarantee about the model.

## GitHub Actions

The [CLI CI/CD integration guide](/docs/cli/ci-cd/) contains a complete GitHub Actions example with Bun, a provider secret, validation and JUnit artifact upload. Adapt its scenario path, provider and version pins to your project.

## GitLab CI

This starting point assumes a valid `scenarios/` directory configured for OpenAI and a CI/CD variable named `OPENAI_API_KEY`. Configure the variable and its protected-branch access in GitLab. The runner needs network access to the model provider; calls may incur charges.

```yaml
artemiskit-evaluation:
  image: oven/bun:1.3.10
  script:
    - bun add -g @artemiskit/cli@0.6.3
    - akit validate scenarios/ --strict
    - akit run scenarios/ --ci --export junit --export-output ./test-results
  artifacts:
    when: always
    paths:
      - test-results/
    reports:
      junit: test-results/*.xml
```

The CLI requires Bun, including when installed with npm. Verify the image and package versions against your environment. Secrets may not be available to untrusted merge-request pipelines; use your platform’s protected-variable and fork policies. Artifacts may contain prompts or model responses, so use suitable data, access and retention rules.

## What should I do when a job fails?

A validation error means the scenario needs attention before a provider call. An evaluation failure or runtime error exits nonzero; inspect the job log and any exported report to distinguish a failed expectation from a provider or configuration problem. A report may be absent when a job stops before export. Model variation and provider outages require investigation rather than an automatic conclusion that a product is unsafe.

For command options see [run](/docs/cli/commands/run/) and [validate](/docs/cli/commands/validate/); for programmatic use see [SDK evaluation](/docs/sdk/evaluation/).
